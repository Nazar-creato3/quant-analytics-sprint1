# ADR 0013 — Сессионные JWT: PyJWT вместо python-jose

Статус: принято 2026-10-06. Основатель заказал смену стека. Закрывает D-01-1 и D-01-3.

## Контекст

`python-jose` 3.3.0 / 3.5.0 тянет `ecdsa` (PYSEC-2026-1325, Fix Versions пуст) и сам содержит CVE-2026-85394 (подмена алгоритма, патча нет). Игноры в `pip-audit` были временными.

## Решение

Сессионные токены подписывает и проверяет **PyJWT 2.15.1**. `python-jose` не остаётся в зависимостях. `ecdsa` и `rsa`, которые шли только через него, из CI-графа убраны.

API сверено с установленным пакетом 2.15.1 и документацией:

- `jwt.encode` возвращает `str`: https://pyjwt.readthedocs.io/en/2.15.1/usage.html
- `jwt.decode(..., algorithms=[...])`: список алгоритмов задаётся кодом, не заголовком токена (предупреждение в той же странице, RFC 8725 §2.1). В продукте это `algorithms=[settings.ALGORITHM]`, по умолчанию `HS256`.
- Обязательные claims: `options={"require": ["exp", "sub"]}` (`jwt.types.Options.require` в том же выпуске).

Заголовок `alg` по-прежнему сравнивается с `settings.ALGORITHM`; `none` отвергается. Это не выбор ключа по `alg` из токена.

## Откат

Откат — revert этого изменения. Возвращать `python-jose` при открытых PYSEC-2026-1325 и CVE-2026-85394 нельзя: игноры CVE не восстанавливать молча.

## Последствия

`pip-audit -r requirements-ci.txt` без `--ignore-vuln` на 2026-10-06: `No known vulnerabilities found`. Полный аудит `requirements.txt` остаётся D-01-2.
