# ADR 0017 — Цикл одобрения и журнал манёвра

Статус: принято 2026-10-07 (промпт 39).

## Контекст

Промпт 34 оставил журнал в памяти процесса и короткие статусы. Промпт 39 требует машину состояний, повторную проверку перед отправкой, хеш-цепочку и PDF. Машина заявок live — промпт 24, его ещё нет.

## Решение

1. Переходы живут в `maneuver_cycle.machine`. `act_desk.decide` / `send` / `execute` / `close_maneuver` — единственные писатели статуса, когда включён `qa_maneuver_cycle`.
2. Правка заново вызывает `preview_orders`, а не отдельную формулу влияния.
3. Отправка читает цену через `load_market_price`. Нет цены — «нет данных», без выдуманной котировки.
4. Paper — книга 05 и идемпотентный ключ манёвра. Live не исполняется, пока выключен `qa_act_live` и пока нет промпта 24.
5. Журнал — одна хеш-цепочка. Файл включается переменной `QA_MANEUVER_JOURNAL_DIR`. PDF строится из тех же строк.
6. Откат: `FF_QA_MANEUVER_CYCLE=0`.

Новых библиотек нет. PDF — уже стоящий ReportLab, иначе минимальный PDF, как в отчёте промпта 20.

## Отвергнуто

Отдельная таблица `Maneuver` торгового бота не становится журналом советника: это другой объект (промпт 34). Клиентский признак «второй фактор пройден» не принимается: его можно подделать, а проверка TOTP в этот шаг не включается, потому что live выключен.
